# Request

Make the scanner its own open-source repository, with the same agent workflow as the application it grades: "Follow this bootstrap", with the interview answered from what we already knew instead of asked one by one.

## Reasoning

The scanner had grown into a separate service with its own database, API, image and tests, and the aim was trust: anyone can read exactly how a grade is produced. A separate repository keeps the application's history and private files out of a public codebase. History for the scanner folder was extracted with `git filter-repo`, scanned with gitleaks, and kept.

Interview answers (all inferred, then confirmed by the owner):

- Project: mcp-connectors-scanner. Grades connectors A to F from evidence.
- Agent: Claude Code only. Posture: trusted developer (not bypass), because the repository is public and takes outside contributions.
- Language: Python. Architecture: flat, modules by topic.
- Web app: no (it serves a small read-only API). LLM in the request path: no. Reads environment variables: yes.
- Customer-visible surfaces, UI components, governed metrics, frontend: no. Testing discipline: yes.
- License: Apache 2.0, held by Sciensoft Technologies B.V. External contributions: accepted.

Decisions made while scaffolding, which differ from the stock templates:

- Security and conduct contacts: the templates assume a security address at the project domain, which does not exist. Reports go to GitHub private vulnerability reporting first, then the Sciensoft contact form, then the hello address. Public issues are for bugs and ideas only.
- `best-practices.md` is the stub variant, trimmed: the stock stub describes repository, service and dependency-injection layers that this flat codebase does not use. Refinement from current sources is still to do.
- The decision record from the application repository was rewritten for a standalone repository and renumbered 0001.
- The compose file joins the application's existing network and has the database service commented out, because the scanner shares an existing Postgres.

## Output

Agent brief and rules (`AGENTS.md`, `CLAUDE.md`, `.agents/rules/`), Claude settings and hook, ADR and todo folders, security methodology, Apache 2.0 license, README, contributing guide, code of conduct, security policy, issue and pull request templates, Python tooling and Makefile, pre-commit with gitleaks, standalone compose file and env example, and the persisted answers in `.agents/bootstrap.json`.
