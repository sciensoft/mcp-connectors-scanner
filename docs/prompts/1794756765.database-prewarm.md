# Download the vulnerability databases once, before the workers

## Request
Run 8 of the sweep failed many scans with "failed to download vulnerability DB". The user asked to download the databases once up front, let the parallel work use what is there, and agreed to a disk-backed temp folder on the cache volume.

## Reasoning
- 32 workers raced to download the same database, and the 954 MB Java database could not fit the 512 MB in-memory /tmp.
- Trivy writes its download archive to TMPDIR, so a scratch folder on the cache volume fixes the size problem. It was tested with only 8 MB of /tmp.
- TMPDIR is set only on the download command (`env TMPDIR=...`), so scan temp files stay where they were.
- A missing database must stop the sweep. Scanning without it would hide vulnerabilities behind a good-looking grade.

## Consulted rules
- .agents/rules/workflow-security.md
- .agents/rules/workflow-testing.md

## Output
- engine/scan.py: `prepare_databases`, scratch folder helpers, both skip flags on every Trivy scan.
- engine/main.py: the sweep calls the warm-up first and stops if it fails.
- tests/test_prepare_databases.py and two sweep-order tests: 75 tests pass.
- Run 9 on the real system: no download failures, A 84, B 4, C 106, D 74, not assessed 32.
- docs/decision-log.md and docs/guide.md updated.
