# Move the scanner onto private networks

## Request
Isolate the scanner stack with the main application's network work: the database is private,
the scanner API is reachable only by the server and the CI runner, and the scanner keeps its
own route to the internet.

## Reasoning
The scanner used to share one network with the server and the database. It now joins two
internal networks created by the main repository's compose file (`mcpc_db` for the shared
Postgres, `mcpc_scan` for its API) and its own `scanner_out` network for the registries,
vulnerability databases and GitHub. `scanner_out` is not shared with the server, so a
compromised server cannot borrow the scanner's internet access. No fixed addresses: podman-compose
turns one `ipv4_address` into a single `--ip`, which podman rejects on a multi-network
container, so peers are reached by name through podman DNS. The CI runner was joined to
`mcpc_scan` with `podman network connect` because recreating it needs a fresh registration token.

## Consulted rules
workflow.md - prompt file; workflow-security.md - network exposure, no secret printed or
committed; workflow-todos.md - nothing satisfied or deferred here (the runner's trust review
is tracked in the main repository).

## Output
- `docker-compose.yaml`: scanner on `mcpc_db`, `mcpc_scan`, `scanner_out`; init job on `mcpc_db`;
  comments updated to point at the audit in the main repository.
- `Makefile` and `deploy/sweep-once.sh`: same three networks; `scanner_out` must exist
  (`podman network create scanner_out`, or let the compose file create it).
- Verified on the live stack: the scanner reaches its database and the server's feed, the server
  and runner reach the API, the runner cannot reach the database.
