# Request

Validate the three scanner units that were in /etc/systemd/system but not in the repo (`mcpc-scanner.service`, `mcpc-scanner-sweep.service`, `mcpc-scanner-sweep.timer`), reconcile them with `mcp-connectors-scanner.service`, and fix the defect where the scanner container ignores SIGTERM.

## Reasoning

`mcpc-scanner.service` duplicated the repo's unit, was disabled, had never run and had no `User=`, so it would have run a root podman. The sweep service had no `User=` either, so it would have failed against an empty root podman. The weekly sweep was already live as a user timer (last run 16 November). The sweep units now live in `host/` with user and path placeholders, installed by `make host-install`, and the live user timer was swapped for the system one with the same schedule, so only one runs. The old files were backed up to the owner's `backups/old-units` folder first. The SIGTERM fix is `--init` on the scanner and sweep containers (catatonit forwards the signal); it was verified: a stop under the unit went from 30 seconds and exit 137 to about a second and exit 143.

## Consulted rules

workflow.md — per-task loop (prompt file, single commit, push)
workflow-security.md (n/a — no secrets, ports or exposure change; units run as the owner, not root)
workflow-todos.md — the SIGTERM todo removed in the same commit as its fix

## Output

- New `host/mcp-connectors-scanner-sweep.service` and `.timer`; Makefile `host-verify`, `host-install`, `host-uninstall` cover all three units, new `host-timer-enable`.
- `--init` in the scanner's `podman run` and in `deploy/sweep-once.sh` (also fixed a wrong default name in its comment).
- `deploy/README.md` updated; `docs/todos/scanner-container-ignores-sigterm.md` removed.
