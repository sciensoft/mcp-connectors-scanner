# Publish the scanner and database versions with every result

## Request
The user asked whether the vulnerability database should be published as an asset with each scan release. Decision: no raw dump, but record which database versions and tool versions each scan used, and run one more full scan and publish it so it shows on the Actions page.

## Reasoning
- The Trivy databases are public data from other projects and several gigabytes. Re-publishing them adds size, not clarity.
- Our own scan database can hold internal details, and full.json is already its scrubbed export.
- What makes a scan reproducible is knowing which tool versions and which database snapshot it used, so those go into the published metadata.
- A missing piece is reported as null, never guessed.

## Consulted rules
- .agents/rules/workflow-security.md
- .agents/rules/workflow-testing.md

## Output
- engine/versions.py reads tool versions and the database metadata files (version, updated, downloaded only).
- engine/api.py: new authenticated /v1/versions endpoint.
- deploy/collect.py: meta.scanner in both summary.json and full.json, passed through the scrubber.
- tests/test_versions.py and two collector tests: 83 tests pass.
