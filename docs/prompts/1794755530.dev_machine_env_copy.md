# Request

Copy the scanner's environment file to the development machine (hrollers) so the scanner also runs there, and recreate the credentials later.

## Reasoning

Generating new values on the development machine was the cleaner idea and was offered first, but the development setup runs the application and the scanner together and they must reach each other. The owner chose the shortcut for now: the same values as production, with the credentials to be recreated later. It is a development machine and the owner accepted that the values would pass through a connector call log.

The file was moved without printing it in the conversation and without SSH, which is closed on that machine: encoded on production, decoded into place on the development machine with owner-only permissions, then verified by checksum (identical on both). The encoded temporary file on production was shredded. Git ignores the file on both machines, and the development clone is clean and on the same commit as GitHub.

## Consulted rules

workflow-security.md (a secrets file copied between machines, call log exposure).

## Output

- `.env` on the development machine, mode 600, identical to production's by checksum, gitignored.
- `docs/todos/dev-machine-credentials.md`: recreate the credentials so the two machines share no secret.
