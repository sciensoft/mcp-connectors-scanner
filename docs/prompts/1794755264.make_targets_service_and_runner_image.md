# Request

Run the scanner on the production machine with its own local environment file (gitignored), keep it running as a service like the application's own, and give the Makefile the same container management targets as the application repository (up, down, restart, rebuild).

## Reasoning

The stock Makefile came from the bootstrap template: its `clean` target ended with leftover template text and `run` was a placeholder. It now has the application's names (`up`, `down`, `restart`, `rebuild`, `logs`, `ps`) plus `serve`, `sweep` and service and timer install targets.

The container is started with plain `podman run`, not podman-compose, because podman-compose 1.0.6 on this machine cannot resolve the compose file's init-step dependency. The run flags live in one place in the Makefile and are shared by `up` (detached) and `serve` (foreground).

The service first written was a one-shot unit that only created the container and left restarts to the container engine, which would not have matched the request. It was rewritten: systemd runs the container in the foreground through `make serve` and restarts it on failure, as the application's unit does. The engine's own restart policy is switched off in that mode so two supervisors do not fight over one container.

Secrets live in `.env` (gitignored, mode 600), copied from the production environment file; `.env.example` lists the names and no values. The one-shot sweep script now reads that same file by default.

A runner image is written but not built or registered yet: no sudo, no docker group, no container engine inside, runner tarball verified against the checksum GitHub publishes.

## Consulted rules

workflow-security.md (secrets files, a runner on a public repository), workflow.md (prompt file shape).

## Output

- `Makefile` rewritten; `deploy/systemd/mcpc-scanner.service` added; `deploy/systemd/mcpc-scanner-sweep.service` and `deploy/sweep-once.sh` updated to the new env file location.
- `.env.example` updated to match what the service reads.
- `deploy/runner/Containerfile` and `entrypoint.sh` added (not yet built).
- Verified on the live machine: the service took over the container, the server reads grades from the scanner, the scanner reads the catalog from the server.
