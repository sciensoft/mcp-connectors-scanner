# Request

The weekly publish workflow kept failing and sending failure emails. Find out why, then fix it in the compose file, and rename `docker-compose.yaml` to `compose.yaml`.

## Reasoning

The sweep itself was healthy. The failing step was "Confirm a recent scan exists", which died with `Name or service not known`: the self-hosted runner container sat only on `mcpc_vnet`, while the scanner API (`mcp-scanner`) is on `mcpc_db`, `mcpc_scan` and `scanner_out`. They shared no network, so the name did not resolve. The runner had been started by hand with `podman run`, so its networks were lost when it restarted on 2026-11-22. That restart also produced repeated "a session for this runner already exists" errors, because the registration files were not kept anywhere. The 15 Nov failure was a different cause (401, a wrong token) and was already fixed.

## Consulted rules

workflow.md — per-task loop (prompt file, single commit, push)
workflow-security.md — touches a network-attached container: the runner joins `mcpc_scan` (private, no route out) and `scanner_out`, keeps `cap_drop: ALL` and `no-new-privileges`, and receives no database or scan secrets; the registration token defaults to a placeholder and is never stored in the repo

## Output

- `docker-compose.yaml` renamed to `compose.yaml`; references updated in `.env.example`, `deploy/sweep-once.sh`, `docs/guide.md`.
- New `scanner-runner` service in `compose.yaml` on `mcpc_scan` and `scanner_out`, with a named volume `runner_state` over the runner folder so a restart keeps its registration. Trade-off noted in the file: a newer runner version in a rebuilt image only takes effect after removing the volume and registering again.
- Old prompt records still mention the old file name; they are history and were left alone.
